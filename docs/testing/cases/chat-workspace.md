# 中间对话工作区测试用例

## CW-001 空工作区

前置条件：没有当前会话消息。

步骤：

1. 打开创作页面。
2. 查看中间区域。

期望：

- 展示引导文案和底部输入框。
- 不展示假的最近会话或 demo 文案。
- 右侧手机预览为空态。
- 后端没有新增 Conversation。
- 即使存在历史记录，也不自动激活最近一条。

## CW-002 发送后出现用户消息

前置条件：输入框为空。

步骤：

1. 输入“写一篇儿童摄影活动公众号文案，面向家长，风格温暖。”
2. 点击发送按钮。

期望：

- 输入内容立即作为用户消息出现在对话列表。
- 输入框清空。
- 资源引用随消息展示。
- 不需要用户确认执行计划。
- 首次发送成功后历史列表才新增 Conversation。

## CW-003 AI 可见回复流式输出

前置条件：Run 已创建，SSE 正常连接。

步骤：

1. 后端发送 `assistant.message.created`。
2. 后端连续发送多个 `assistant.message.delta`。
3. 后端发送 `assistant.message.completed`。

期望：

- 对话列表出现 AI 消息气泡。
- 内容随 delta 追加。
- completed 后停止流式光标或 loading 状态。
- 消息内容不包含内部思维链、工具参数或 prompt。

## CW-004 任务卡流式更新

前置条件：Run 已创建。

步骤：

1. 后端发送 `task.card.updated`，状态为 `running`。
2. 后端更新步骤“需求理解”为 `completed`。
3. 后端更新步骤“正文写作”为 `running`。
4. 后端发送 `run.completed`。

期望：

- 任务卡出现在对话列表中。
- 步骤状态随事件更新。
- 完成后任务卡自动收起。
- 右侧预览区域不展示任务状态条。

## CW-005 信息不足时追问

前置条件：用户只输入“帮我写一篇文章”。

步骤：

1. 点击发送。
2. 后端发送 `clarification.required`。
3. 用户选择或输入补充信息并提交。

期望：

- 对话列表出现追问卡。
- 任务卡状态变为 `waiting_clarification`。
- 用户补充后原 Run 继续。
- 追问文案是补充信息，不是计划确认。

## CW-006 Artifact 更新右侧预览

前置条件：Run 正在执行。

步骤：

1. 后端发送 `artifact.created`。
2. 前端拉取 artifact。

期望：

- 右侧手机预览刷新。
- 对话列表插入结果通知。
- 最终正文不包含用户原始输入、执行计划、AI 过程或审阅说明。

## CW-007 Run 失败

前置条件：Run 正在执行。

步骤：

1. 后端发送 `run.failed`。

期望：

- 任务卡保持展开。
- 展示用户可理解的失败原因。
- 如果 `retryable` 为 true，展示重试入口。
- 右侧预览不把半成品当作最终内容。

## CW-008 旧事件兼容

前置条件：后端仍发送旧事件 `step.started`、`step.completed`、`decision.required`。

步骤：

1. 接收 `step.started`。
2. 接收 `step.completed`。
3. 接收 `decision.required`。

期望：

- 步骤事件映射到任务卡。
- `decision.required` 映射为追问卡。
- 页面不出现“确认计划”按钮。

## CW-009 独立滚动

前置条件：对话列表已有多条消息。

步骤：

1. 缩小浏览器高度。
2. 滚动中间对话列表。
3. 查看页面整体和右侧预览。

期望：

- 页面整体没有主滚动条。
- 中间消息列表独立滚动。
- 输入框固定在中间面板底部。
- 右侧预览独立滚动。

## CW-010 历史重新排序

前置条件：历史列表已有 A、B 两条 Conversation，B 排在第一条。

步骤：

1. 打开 A。
2. 在 A 中发送新的用户消息。
3. 等待发送接口成功。

期望：

- A 移动到第一条。
- 标题仍为 A 的首条 prompt。
- AI 后续输出不再次改变排序时间。

## CW-011 多资源紧凑展示

前置条件：本地空会话。

步骤：

1. 选择 6 张图片。
2. 等待上传完成。
3. 点击发送。

期望：

- 输入区和用户消息最多展示 4 张 `44 × 44` 缩略图。
- 其后显示 `+2`。
- 点击 `+2` 可以查看全部 6 张。
- 发送成功后不显示单张删除按钮。

## CW-012 删除会话

前置条件：当前打开一个已有 Conversation。

步骤：

1. 在历史项菜单点击删除。
2. 确认删除 Conversation。

期望：

- 删除接口返回后该项立即从历史移除。
- 当前区域回到新的本地空会话。
- 不提供只删除一条消息或一张已发送图片的入口。

## CW-013 顶部账户区

前置条件：用户已登录，当前用户为 `admin`，角色为 `Owner`。

步骤：

1. 打开创作页面。
2. 查看顶部栏右侧。
3. 点击账户区域。
4. 键盘聚焦账户区并打开账户面板。

期望：

- 顶部栏左侧品牌展示不变。
- 顶部栏不展示 `准备就绪`。
- 顶部栏不展示 `新建创作`。
- 顶部栏右侧展示账户胶囊，包含头像和 chevron。
- 点击账户区域后展示账户面板。
- 账户面板包含头像、`admin`、`Owner` 和 `默认团队`。
- 账户面板包含 `账号安全`、`权限范围`、`系统设置` 三个入口。
- `退出登录` 是账户面板底部的全宽描边按钮。

## CW-014 退出登录

前置条件：用户已登录并停留在创作页面。

步骤：

1. 点击顶部账户区。
2. 点击账户面板底部的 `退出登录`。
3. 等待退出请求完成。

期望：

- 前端调用 `POST /auth/logout`。
- 登录 Cookie 被清理。
- 页面跳转到 `/login`。
- 退出后再次访问 `/` 会被路由守卫跳转到 `/login?next=%2F`。
- 如果退出请求失败，用户仍停留在当前页面并看到可理解错误提示。

## CW-015 Agent 流式过程面板

前置条件：Run 正在执行，SSE 持续发送 `agent.*` 事件。

步骤：观察多个 Agent 依次执行。

期望：当前 Agent 自动展开；摘要按 sequence 追加；已完成 Agent 折叠；阶段、耗时和最近活动时间持续更新。

## CW-016 Run 完成自动收起

步骤：等待 `run.completed` 和 Artifact 加载完成。

期望：所有 Agent 面板自动收起；任务卡可以手动重新展开；右侧只显示最终文章。

## CW-017 Agent 失败保持展开

步骤：让模型校验重试后仍失败。

期望：失败 Agent 保持展开；显示失败阶段和可理解错误；生成按钮退出等待状态；不得静默结束。

## CW-018 长时间无模型增量

步骤：模型 20 秒没有返回 delta，但持续收到 heartbeat。

期望：页面显示“模型仍在处理”和最新耗时；不会清除 activeRunId，也不会显示完成。

## CW-019 SSE 断线恢复 Agent 摘要

步骤：接收部分 Agent 增量后断网，再使用 `Last-Event-ID` 重连。

期望：只补发未读事件；相同 step sequence 不重复追加；当前 Agent 和折叠状态恢复正确。

## CW-020 失败 Run 的右侧预览状态

步骤：模拟 `run.failed`，且本次 Run 没有产生 `artifact.created`。

期望：任务卡显示“失败”及中文原因，失败步骤保持展开；右侧显示“本次未生成预览”，发送按钮恢复可用，不继续展示其他 Run 的旧预览。

## CW-021 固定三栏与横向滚动

前置条件：页面存在历史会话、对话内容和最终 Artifact。

步骤：

1. 分别以 `1920×1080`、`1366×768`、`1280×720` 和 `1024×768` 打开创作页面。
2. 检查三栏计算宽度和工作台滚动尺寸。
3. 在低宽度下横向滚动至右侧预览。

期望：

- 中间创作区不小于 `720px`，右侧预览区始终为 `400px`。
- `1280px` 和 `1024px` 下工作台外层出现横向滚动，三栏不压缩、不自动切为单栏。
- 页面不产生纵向主滚动；左、中、手机内容继续独立纵向滚动。
- 左栏折叠只减少左栏占用，不改变中间和右侧的最小尺寸。

## CW-022 手机内容视口跨分辨率一致

前置条件：固定 Artifact 包含长标题、多个段落、横图、长图和章节装饰。

步骤：

1. 在测试分辨率下依次打开同一 Artifact。
2. 记录手机文章根节点宽度、标题行数、段落行数和图片位置。
3. 缩小浏览器高度和宽度后重复检查。

期望：

- 手机内容视口始终为 `390 × 844 CSS px`。
- 标题换行、段落行数、图片宽度和内容顺序在各分辨率下一致。
- 手机逻辑内容未被缩窄或使用 `zoom`，文章只在固定视口内部纵向滚动。
- `scale(0.8)` 只作用于完成排版后的完整手机设备外层。
- 外框边框不计入 `390px` 内容宽度。

## CW-023 Shadow DOM 样式隔离

前置条件：工作台全局样式和 Artifact 内联样式都包含 `section`、`p`、`img` 等通用标签规则。

步骤：

1. 加载 Artifact 预览。
2. 检查文章节点计算样式。
3. 检查工作台同名标签和控件样式。

期望：

- Artifact 挂载在 ShadowRoot 中，页面不存在预览 iframe。
- 工作台全局 CSS 不改变文章字体、间距、颜色和图片尺寸。
- Artifact 样式不改变工作台工具栏、消息区和按钮。
- ShadowRoot 显式提供字体回退、背景、box model 和图片宽度约束。

## CW-024 Artifact HTML 安全清洗

前置条件：测试 Artifact 混入 `script`、`onclick`、`javascript:` 链接、未知远程图片和允许的文章标签及内联样式。

步骤：

1. 加载测试 Artifact。
2. 检查 ShadowRoot 实际挂载内容和网络请求。
3. 点击保留下来的文本与链接区域。

期望：

- 脚本和事件属性被移除且无法执行。
- 危险 URL、未知远程资源和不允许节点被阻断。
- 允许的文章结构、图片和安全内联样式正常显示。
- 清洗后再挂载，不存在未经清洗 HTML 的普通 DOM 或 Shadow DOM 注入路径。

## CW-025 资源解析、源码与复制边界

前置条件：Artifact 同时包含 `/resources/...`、`/user-skills/assets/...`、未知路径和普通正文中的相似字符串。

步骤：

1. 打开手机预览并检查图片请求地址。
2. 切换到源码模式。
3. 点击复制 HTML 并读取剪贴板内容。
4. 模拟一张图片加载失败。

期望：

- 只通过 DOM 节点遍历转换允许的资源属性，正文中的相似字符串不被修改。
- 未授权或未知资源不加载。
- 图片失败显示稳定占位，不改变手机内容宽度。
- 源码和剪贴板内容保持原始 Artifact HTML，不包含 Shadow DOM 包装、预览基础样式或清洗后的序列化结果。

## CW-026 预览异常降级

步骤：分别模拟清洗后内容为空、ShadowRoot 创建失败和 Artifact 更新过程中解析失败。

期望：右侧显示可理解的预览错误；不得回退为普通 DOM 注入；源码和复制 HTML 仍可使用；上一个 Artifact 的节点和事件监听不残留。

## CW-027 桌面紧凑手机预览

前置条件：固定 Artifact 包含长标题、多段正文和多张图片。

步骤：

1. 在 `1920 × 1080` 下打开创作页面并记录手机逻辑尺寸、设备视觉尺寸、右栏和中间区宽度。
2. 在 `1440 × 900`、`1366 × 768` 和 `1280 × 720` 下重复检查。
3. 对比各分辨率下标题行数、段落行数和图片位置。

期望：

- ShadowRoot 和文章逻辑视口始终为 `390 × 844px`。
- 完整 `410 × 864px` 手机设备固定以 `80%` 展示，视觉尺寸约为 `328 × 691.2px`。
- `DeviceStage` 占据缩放后的视觉尺寸，不保留 `410 × 864px` 的空白布局占位。
- 右侧预览区固定为 `400px`，`1920 × 1080` 下兼容性提示完整可见且中间创作区明显宽于第一阶段方案。
- `1440px` 下展开状态三栏基本完整显示；`1280px` 下允许横向滚动，但滚动距离小于 `520px` 右栏方案。
- 各分辨率下标题换行、段落行数、图片位置和内部滚动行为一致。
- 源码展示和复制 HTML 不包含视觉缩放包装，也不因缩放发生变化。
