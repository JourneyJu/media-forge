# 最小改动规范

## 原则

- 只改完成当前任务必须改的文件。
- 不顺手重构无关代码。
- 不因为发现“可以更优雅”就扩大范围。
- 先遵循现有结构，再考虑抽象。
- 新抽象必须解决真实重复或复杂度，不能为了形式。

## 文件边界

实现前声明 `allowed_files`。实现中需要新增文件时，先说明原因并更新边界。

## 允许的小调整

- 修复同一文件内直接相关的命名或类型错误。
- 补齐当前改动必须依赖的导出。
- 为当前行为增加最小测试。

## 需要暂停确认

- 改动扩散到新模块。
- 需要新增依赖。
- 需要改数据库 schema。
- 需要调整服务边界。
- 需要改变用户可见流程。
