# SQL 与数据库规范

本规范适用于 PostgreSQL schema、迁移、查询和数据访问代码。

## 数据源边界

- PostgreSQL 是业务事实数据源。
- MinIO / S3 只保存图片、HTML 快照、Markdown 导出、prompt 快照、skill 包等对象。
- 数据库保存对象元数据和对象 key，不保存大文件二进制。
- Redis 不保存不可丢失的业务事实。

## 命名

- 表名使用 snake_case 复数，例如 `workspaces`、`article_versions`。
- 字段名使用 snake_case。
- 主键使用 `id`。
- 外键使用 `{entity}_id`，例如 `workspace_id`、`article_id`。
- 时间字段统一使用 `created_at`、`updated_at`、`deleted_at`。

## 多租户与归属

- 用户或组织归属数据必须有租户、用户或工作区上下文字段。
- 查询时不能只按资源 id 查询后直接返回；必须同时校验归属上下文。
- 对象存储 key 不能替代数据库归属关系。

## 字段设计

- 可编辑文章结构使用结构化字段或 `jsonb`，但必须有版本号和 schema 说明。
- HTML 快照、导出文件、prompt 快照只保存对象 key 和元数据。
- 状态字段使用稳定枚举值，不使用自由文本。
- 大数字如 token、配额、文件大小使用整数并明确单位。

## 索引与约束

- 外键字段、常用查询条件、唯一业务键需要索引。
- 幂等写入依赖唯一约束，不只靠应用层判断。
- 软删除数据如果需要唯一约束，必须考虑 `deleted_at` 或状态条件。

## 事务

- 一个业务动作涉及多表事实变更时必须使用事务。
- 对象存储写入和数据库写入不能真正原子化时，要设计补偿状态。
- 外部 AI 调用不要长时间占用数据库事务。

## 迁移

- schema 变更属于 L 级，必须先在 `.plan/` 写计划并确认。
- 迁移需要说明升级步骤、回滚策略、数据修复方式和验证 SQL。
- 生产数据删除、字段语义改变、批量重写必须有人工确认。

## 查询

- 不拼接用户输入生成 SQL。
- 列表查询必须有分页和稳定排序。
- 后端 repository 层负责 SQL 细节，service 层不直接拼 SQL。
