# 前端服务规范

本规范适用于 `apps/web`。

## 技术栈

- Next.js + React + TypeScript。
- 共享契约来自 `packages/contracts`。
- 前端只调用 `apps/service`，不直连数据库、对象存储、Redis 或模型供应商。

## 目录与职责

- 页面文件只负责路由入口、布局组合和数据装配。
- 可复用 UI 组件放在组件目录；业务组件按功能模块归属。
- hooks 负责前端状态、请求编排和交互逻辑。
- API client 负责和后端通信、错误映射、响应类型收窄。
- 纯展示组件不能直接发请求。

## 组件化

- 组件优先小而稳定，props 表达清楚，不把整个大对象随意透传。
- 跨模块复用前先确认它确实是通用能力，不提前抽象。
- 表单、上传、编辑器、预览、导出等复杂组件必须拆分状态层和展示层。
- 组件内部避免隐藏业务副作用；副作用放 hooks 或调用层。

## TypeScript

- props、hooks 返回值、API client 返回值必须有明确类型。
- 展示层类型优先复用契约，必要时定义 `ViewModel`。
- 不用 `any` 绕过复杂数据结构；对 AI 返回、上传识别结果等不可信数据先校验。

## UI 与交互

- 第一版优先桌面端编辑效率，同时保证主要流程在窄屏不崩。
- 工具型界面保持清晰、稳定、可扫描。
- 文章预览必须明确来自 renderer，不把编辑态随意当作微信最终效果。
- 复制和导出是核心链路，变更前需要说明兼容性和测试方式。
- 用户可见文案使用中文。

## 状态管理

- 局部状态优先放组件内。
- 跨组件但不跨页面的状态放 feature hook。
- 跨页面或需要缓存的状态必须有清晰失效策略。
- 服务端事实以 API 响应为准，前端乐观更新必须能回滚。

## 样式

- 遵循项目既有样式方案，不为单个页面引入新的 UI 框架。
- 固定格式工具元素要有稳定尺寸，避免 hover、加载态、长文案导致布局跳动。
- 按钮、输入、菜单、上传、预览区域需要可访问标签或可读文本。

## 测试

- 组件测试覆盖关键交互、异常态、空态和权限态。
- API client 测试覆盖响应映射和错误映射。
- 复制导出、上传、AI 生成流程需要集成或 E2E 级验证。
