# 模块文档规范

## 原则

- 架构文档只做系统级说明和模块路由。
- 模块文档是单模块事实源。
- API 文档、测试方案、测试用例必须能从模块文档追溯。
- 不在多个地方维护同一份细节。

## 变更链路

```text
架构变更
→ architecture
→ modules/{module}
→ api/{module}.md
→ testing/plans/{module}.md
→ testing/cases/{module}.md
```

## 模块文档最低要求

每个模块文档至少包含：

1. 模块定位。
2. 职责边界。
3. 领域对象。
4. 状态和流程。
5. 数据归属。
6. API 路由。
7. 测试路由。
8. 风险。

## 需要同步 API 和测试的情况

- 新增或修改接口。
- 修改请求或响应字段。
- 修改错误码。
- 修改权限。
- 修改状态机。
- 修改数据写入、删除、上传、导出流程。
- 修改 AI 调用链路。
