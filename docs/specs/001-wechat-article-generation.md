# 规格：微信公众号生成功能

## 背景

MediaForge 第一版面向培训机构、本地门店和兼职运营人员，帮助普通用户生成可复制到微信公众号后台的图文内容。该功能不直接发布到微信公众号，而是提供结构化编辑、AI 生成、微信兼容 HTML、历史版本和复制导出能力。

## 目标用户

| 用户 | 场景 |
| --- | --- |
| 培训机构校区负责人 | 招生宣传、公开课、课程介绍、学员案例。 |
| 课程顾问或教务 | 家长沟通、活动通知、报名引导。 |
| 门店老板或店长 | 促销活动、新品推荐、会员福利、门店介绍。 |
| 兼职运营人员 | 快速产出公众号图文并复制发布。 |

## 产品范围

### 第一版必须支持

- 在工作区内创建公众号文章草稿。
- 输入主题、受众、卖点、CTA、语气、风格和补充说明。
- 上传图片、二维码、海报和视频素材。
- 使用 AI 生成结构化 `ArticleDocument`。
- 使用微信兼容 renderer 生成 HTML。
- 保存文章版本，包含 `content_json`、HTML 快照 key、prompt 快照 key、renderer 版本。
- 手机比例预览、源码查看、复制到公众号。
- 通过对话修订文章内容。
- 在当前会话中展示 Agent 执行计划、步骤进度、审阅问题和用户确认；前端可用计划条或对话消息承载，不再要求独立 Agent 控制台。
- 按“素材理解 → 计划 → 排版 → 扩充 → 审阅 → 重构/修订 → 终审”执行可恢复工作流。
- 显示微信兼容性 warning。

### 第一版不支持

- 不直接发布到微信公众号。
- 不接入微信素材库。
- 不保证视频复制到微信后台后保留播放能力。
- 不支持多人协同。

## 工作台信息架构

| 区域 | 内容 |
| --- | --- |
| 工作区侧边栏 | 工作区入口、新建工作区、真实会话入口。没有真实数据时不展示假会话。 |
| 对话创作区 | 用户自然语言输入、素材上传、`@ Skill`、发送按钮、追问回答和继续调整。 |
| 计划区 | 执行计划、等待确认、完成摘要。任务完成后计划可以收起。 |
| 手机预览区 | 手机比例公众号预览、微信 HTML 源码、复制、兼容性 warning。 |

## 核心流程

### 生成初版

```text
选择工作区
→ 填写主题和生成参数
→ 上传或选择素材
→ 选择排版 skill
→ 创建生成任务
→ AI 返回结构化文章
→ schema 校验
→ 渲染微信 HTML
→ 保存文章版本
→ 前端展示预览和复制入口
```

### Agent 编排生成

```text
上传或选择素材
→ 素材理解 Agent 生成描述、OCR、类型、质量和位置建议
→ 策划 Agent 生成结构化执行计划
→ 当前会话展示计划，前端可用计划条承载
→ 命中确认策略时进入 waiting_user
→ 用户确认或修改计划
→ 排版 Agent 先生成 ArticleOutline，不扩写长正文
→ 内容 Agent 按骨架扩充 ArticleDocument
→ 审阅 Agent 输出 ReviewReport
→ 局部问题进入 revise，结构问题进入 restructure
→ 重构后重新扩充和审阅
→ 终审通过后渲染微信 HTML 并保存正式版本
```

Agent 循环必须有界：

- 局部修订最多 2 次，结构重构最多 2 次，总步骤最多 12 步。
- 连续两次审阅评分没有提升时进入 `waiting_user`。
- 达到循环上限时暂停并保留当前最佳版本，不得无限自动执行。
- 每个产生文章变化的步骤保存可恢复版本；失败步骤不得覆盖当前正式版本。

### 用户确认

以下情况必须在当前会话内暂停并请求用户确认：

- 品牌故事与成交转化方向无法同时满足。
- 需要删除用户明确要求保留的内容。
- 重构预计改变超过 30% 的文章结构。
- 素材识别结果与用户描述冲突。
- 多张相似素材需要用户决定保留范围。
- 达到循环上限或连续两次评分未提升。

### 对话修订

```text
用户输入修改指令
→ 后端带入当前 content_json、素材元数据、工作区记忆和历史摘要
→ AI 返回 patch 或完整结构
→ schema 校验
→ 渲染并保存新版本
→ 前端刷新预览
```

### 复制发布

```text
用户点击“复制到公众号”
→ 前端获取当前版本的微信兼容 HTML fragment
→ 检查资源 URL 和兼容性 warning
→ 从当前 ArticleDocument 生成纯文本兜底内容
→ 同一次剪贴板写入同时提供 text/html 和 text/plain
→ 写入导出事件
→ 用户粘贴到微信公众号后台正文编辑器
```

这里的“复制”是富文本剪贴板导出，不是生成、下载或粘贴 `.html` 文件。HTML 只包含正文 fragment，不包含 `html`、`head`、`body`、外部样式表或脚本。微信公众号编辑器优先读取 `text/html`；不支持富文本剪贴板或复制失败时，前端提供纯文本复制降级。

### 第一阶段交付范围

第一阶段只完成从当前文章版本到公众号正文编辑器的最小发布闭环：

- Renderer 将 `ArticleDocument` 转换为微信兼容 HTML fragment，样式全部内联。
- “复制到公众号”同时写入 `text/html` 和 `text/plain` 两种剪贴板 MIME。
- 浏览器不支持富文本剪贴板或授权失败时，允许用户显式复制纯文本并展示原因。
- 手机预览下方展示段落数、图片数和兼容性 warning；复制成功后提示标题、摘要和封面仍需在公众号后台单独设置。
- 图片只使用当前素材链路已经提供的 HTTPS 可访问 URL；不在本阶段新增图片上传、代理、转存或公众号素材库能力。
- 以 Chrome/Edge 中粘贴到真实微信公众号正文编辑器的结果作为最终人工验收依据。

第一阶段不包含：

- 下载 `.html` 文件作为公众号导入方式。
- 图片素材包和图片位置清单。
- 自动填写标题、作者、摘要、封面、原创声明或留言设置。
- 微信公众号草稿箱或发布 API。
- 为本地路径、`blob:`、`data:` 或不可公开访问的图片提供自动转存。

### 复制状态与降级

| 条件 | 行为 |
| --- | --- |
| HTML fragment 可用且浏览器支持 `ClipboardItem` | 同时写入 `text/html` 和 `text/plain`。 |
| 浏览器不支持富文本剪贴板 | 不伪装为完整成功，提示后允许复制纯文本。 |
| 剪贴板权限被拒绝 | 保留页面内容，提示用户重新授权或使用纯文本复制。 |
| 存在图片 URL warning | 明确展示受影响图片；允许用户确认后复制文字和可用图片，不承诺问题图片可被微信获取。 |
| Renderer 失败 | 阻止富文本复制，不记录成功导出事件。 |

导出事件只在剪贴板写入成功后记录。富文本复制和纯文本降级应使用可区分的导出类型，避免把降级结果统计为完整公众号复制。

### 第一阶段交互方案

第一阶段采用右侧手机预览栏内的最小改动方案，不重构现有工作台。左侧创作记录、中间对话创作区、底部输入区、右侧栏宽度和手机预览尺寸保持不变。

右侧手机预览栏只增加以下交互：

1. 顶部主按钮文案由“复制 HTML”改为“复制到公众号”，沿用现有位置、尺寸和主色样式。
2. 手机预览下方增加单行紧凑状态条：左侧显示“{段落数} 段 · {图片数} 图”，右侧显示“{问题数} 项需处理 >”；无问题时右侧显示“可复制”。renderer 版本作为弱化辅助信息保留在状态条下方。
3. 富文本复制成功后，在右侧预览栏底部显示轻量 Toast：标题为“正文已复制”，说明为“标题、摘要和封面需单独设置”。Toast 自动消失，不遮挡手机预览和主按钮。

状态条行为：

- 段落数、图片数和问题数均来自当前文章版本，版本更新后同步刷新。
- 点击“{问题数} 项需处理 >”复用现有兼容性 warning 展示能力，定位具体 warning；第一阶段不新增常驻发布面板或默认确认弹窗。
- 存在非阻断 warning 时仍允许点击“复制到公众号”；复制结果不承诺问题图片可被微信获取。
- Renderer 失败等阻断问题出现时禁用主按钮，并通过现有错误反馈说明原因。
- 复制执行期间主按钮进入加载和防重复点击状态；成功后显示 Toast，失败时不显示成功 Toast。
- 浏览器不支持富文本剪贴板或权限被拒绝时，沿用纯文本降级提示，不自动静默降级。

本阶段明确不调整：

- 工作台三栏布局及各栏宽度。
- 对话卡片、当前对话上下文、重新生成和底部创作输入区。
- 手机预览容器、预览/源码切换及文章展示样式。
- 左侧创作记录和顶部账号区域。
- 新增发布侧栏、发布向导、大型检查面板或默认弹窗。

## 微信兼容性要求

- HTML 必须使用保守标签和内联样式。
- HTML 输出必须是正文 fragment，不得包装完整 HTML 文档。
- 不允许脚本、事件属性、外部 CSS、CSS 变量、动画和复杂定位。
- 图片必须使用 HTTPS 可访问 URL。
- 不输出本地路径、`blob:` URL 或 `data:` URL；对应图片产生兼容性 warning。
- 图片使用块级自适应样式，至少约束 `display:block`、`max-width:100%` 和 `height:auto`。
- 视频块第一版输出发布前 warning，并可渲染为封面图、标题、说明和手动替换提示。
- 预览必须说明是模拟效果，复制结果以微信后台实测为准。

## 模型配置

第一版模型配置放在 `apps/service/.env`，由后端 Model Gateway adapter 读取。前端不接收、不展示、不保存模型 API Key。

建议环境变量：

```text
MODEL_GATEWAY_PROVIDER=
MODEL_GATEWAY_BASE_URL=
MODEL_GATEWAY_API_KEY=
MODEL_GATEWAY_DEFAULT_MODEL=
MODEL_GATEWAY_TIMEOUT_MS=
```

正式产品形态由管理与配额模块维护 `model_configs`，API Key 加密保存，按工作区、场景或租户路由模型。

## 验收标准

- 用户能从空工作区生成一篇包含文字和图片的公众号文章。
- 生成完成后存在文章主记录和至少一个文章版本。
- 版本同时保存结构化 `content_json` 和 HTML 快照 key。
- “复制到公众号”写入的 `text/html` 是正文 fragment，不包含脚本、事件属性、外部 CSS 或完整 HTML 文档包装。
- 同一次复制同时写入与当前文章语义一致的 `text/plain` 兜底内容，Markdown 标记不得原样出现在富文本结果中。
- 富文本剪贴板不可用或权限被拒绝时，用户能看到失败原因并选择纯文本复制。
- 手机预览下方状态条展示段落数和图片数；复制成功 Toast 说明标题、摘要和封面需要单独设置。
- 工作台保持现有三栏结构；右侧仅调整复制按钮文案、预览下方状态条和成功 Toast。
- 状态条准确展示当前版本的段落数、图片数和兼容性问题数，点击问题数可查看既有 warning。
- 成功 Toast 显示“正文已复制”和“标题、摘要和封面需单独设置”，且不遮挡手机预览或复制按钮。
- 含 HTTPS 公网图片的文章粘贴到真实微信公众号正文编辑器后，图片顺序与文章一致；图片是否被微信转存以平台实测为准。
- 模型返回非法结构时不会保存坏版本。
- 图片素材原文件在对象存储中，数据库只保存元数据和 key。
- 前端不出现模型 API Key 输入框。
- 视频素材会产生明确的发布前 warning。
- 用户可以查看 Agent 计划和每一步执行结果，并在 `waiting_user` 状态提交选择。
- Agent 先生成排版骨架，再扩充正文；内容 Agent 不得自行改变章节结构。
- 审阅发现结构问题时能重构、重新扩充并再次审阅，且循环次数受限。
- 每次结构或内容变化都生成可恢复版本。
