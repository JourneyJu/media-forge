# 规格：固定工作台与 Shadow DOM 手机预览

## 状态

固定工作台、Shadow DOM 预览与桌面紧凑预览优化均已实施。

## 背景

当前工作台会在窗口高度或宽度不足时压缩右侧手机外框，iframe 内文章随之以更窄视口重新排版，造成标题换行、段落行数、图片位置和装饰元素在不同桌面分辨率下发生变化。现有 `980px` 单栏断点也与桌面端保持三栏工作流的目标冲突。

产品希望右侧预览保持稳定，中间创作区保持可用最小宽度。当浏览器缩小到 `1280px` 等不足以容纳三栏的宽度时，由工作台整体产生横向滚动，不再压缩任一核心区域。本方案不使用 iframe，也不建设可视化编辑器。

第一阶段按 `390 × 844px` 逻辑视口以 `100%` 展示后，`1920 × 1080` 实机验证表明手机外框在桌面工作台中占用过高、右栏留白偏多，并压缩了主创作区。桌面展示需要在不改变文章逻辑排版的前提下，将完整设备画面固定缩放为 `80%`，同时收紧右侧栏。

## 目标

- 桌面端保持固定三栏工作台，左侧历史栏和右侧预览栏固定宽度，中间创作区具有稳定最小宽度。
- 窗口宽度不足时，工作台外层出现横向滚动，三栏内部布局不变形。
- 手机文章逻辑视口固定为 `390 × 844 CSS px`，不使用百分比、视口高度或容器压缩改变内容排版宽度。
- 桌面工作台默认将已经完成排版的完整手机外框固定缩放为 `80%`，只改变视觉尺寸，不改变 Shadow DOM 逻辑尺寸。
- 右侧预览栏收紧为 `400px`，使预览保持辅助地位并为中间创作区释放宽度。
- 最终 Artifact HTML 经安全清洗后挂载到 Shadow DOM，避免工作台样式与文章样式互相污染。
- 预览、源码和复制 HTML 继续使用同一份 Artifact；预览转换不得改变复制结果。
- 保持左侧历史、中间消息和手机文章各自独立纵向滚动。

## 非目标

- 不实现点击段落编辑、拖拽图片、局部可视化排版或其他可视化编辑能力。
- 不把 Artifact HTML 转换成另一套 React Block Renderer。
- 不改变 ArticleDocument、Artifact、API、数据库 schema 或 AI 生成链路。
- 不追求不同微信版本、操作系统和系统字体之间绝对像素一致。
- 不在本次实现移动端工作台；小于桌面适用宽度时仍允许横向查看完整三栏。

## 需求分级与影响面

本需求为 M 级：改变用户可见的前端布局和 HTML 渲染安全边界，并新增 HTML 清洗生产依赖，但不改变服务边界、接口、schema 或 AI 调用链路。

影响范围：

- `apps/web` 工作台网格、响应式断点和滚动归属。
- `apps/web` 手机预览组件、Shadow DOM 生命周期、HTML 清洗和资源地址解析。
- 前端单元测试、组件测试和 Playwright 视觉回归测试。
- `chat-workspace` 模块事实和测试文档。

## 页面布局

桌面工作台由一个横向滚动容器承载：

```text
WorkbenchViewport（只负责横向滚动）
└─ Workbench（固定最小宽度）
   ├─ ConversationHistory：260px；折叠后 72px
   ├─ ChatWorkspace：min 720px；宽屏吸收剩余空间
   └─ PreviewPanel：400px
      ├─ PreviewToolbar
      ├─ DeviceStage：328 × 691.2px
      │  └─ DeviceScaler：410 × 864px，scale(0.8)
      │     └─ PhonePreview：390 × 844px 逻辑内容
      ├─ SourceView
      └─ CompatibilityFooter
```

基准尺寸：

| 区域 | 尺寸规则 |
| --- | --- |
| 左侧历史栏 | `260px` 固定，折叠后 `72px` |
| 中间创作区 | 最小 `720px`，宽屏可扩展 |
| 右侧预览区 | `400px` 固定，不收缩 |
| 手机文章逻辑视口 | `390 × 844px` 固定 |
| 手机完整外框 | `410 × 864px`，包含边框，不参与文章内容宽度计算 |
| 桌面视觉比例 | 固定 `80%` |
| 桌面视觉外框 | 约 `328 × 691.2px` |
| 栏间距 | 使用现有 `18px` 间距 |

展开左栏时工作台基准最小宽度约为 `1438px`，折叠左栏后约为 `1250px`。最小宽度必须由上述列宽、间距和页面内边距统一计算，不在多个媒体查询中维护互相矛盾的常量。左栏折叠时允许同步降低工作台最小宽度，但不得改变中间区最小宽度或右侧宽度。

## 响应式和滚动规则

- 可用宽度足够时，工作台占满页面，中间创作区吸收额外空间。
- 可用宽度不足时，`WorkbenchViewport` 出现横向滚动；Grid 列不得收缩。
- `1440px` 桌面分辨率应基本完整容纳展开状态的三栏工作台。
- `1280px` 桌面分辨率必须进入横向滚动状态，并保持手机逻辑内容视口为 `390px`，滚动距离应小于第一阶段 `520px` 右栏方案。
- 删除或调整当前把桌面工作台切为单栏的 `980px` 规则，避免覆盖固定三栏策略。
- 页面纵向不滚动；顶部栏保持固定，三栏内容分别管理纵向滚动。
- 工作台横向滚动、左栏纵向滚动、中栏纵向滚动和手机文章纵向滚动不得互相抢占。
- 生成完成后不得强制改变用户横向位置；后续可以增加显式“查看预览”操作滚动到右侧，但不属于本次必需范围。

## 无 iframe 预览结构

```text
PhonePreview
└─ DeviceStage：328 × 691.2px，占据缩放后的布局空间
   └─ DeviceScaler：410 × 864px，transform: scale(0.8)
      └─ DeviceFrame：固定外框
         └─ PreviewViewport：390 × 844px，纵向滚动
            └─ ShadowRoot
               ├─ PreviewBaseStyles
               └─ PreviewRoot
                  └─ Sanitized Artifact HTML
```

实现采用原生 `attachShadow({ mode: "open" })`，不为 Shadow DOM 生命周期额外引入 React 包装库。Artifact 更新时重建经过清洗的 `DocumentFragment` 并替换 ShadowRoot 内容，不直接把未经清洗的字符串写入页面 DOM。

ShadowRoot 内必须显式设置：

- 宿主和根节点固定宽度、背景和字体回退。
- 全节点 `box-sizing: border-box`。
- 根节点默认 margin 为零。
- 图片 `max-width: 100%`、`height: auto`，禁止撑破视口。
- 工作台全局样式不能进入文章；文章样式不能作用于工作台。

### 逻辑视口与视觉缩放边界

- ShadowRoot、`PreviewViewport` 和文章布局始终按 `390 × 844px` 计算。
- `DeviceScaler` 只能包裹完整的 `410 × 864px` 手机外框，并使用固定 `transform: scale(0.8)` 和 `transform-origin: top left`。
- `DeviceStage` 必须显式占据缩放后的约 `328 × 691.2px`，防止 CSS transform 不改变布局尺寸而产生空白或溢出。
- 禁止对 `PreviewViewport` 本身设置更窄的 width，也禁止使用 `zoom`、`dvh` 或连续动态比例改变文章排版。
- 默认比例固定为 `80%`，不根据窗口高度连续变化，保证桌面视觉尺寸稳定。
- `100%` 原尺寸查看可作为后续独立查看层能力，不得在 `400px` 右栏内直接撑宽工作台，本阶段不要求实现。

## HTML 安全边界

取消 iframe 后，Shadow DOM 只提供样式隔离，不提供脚本安全沙箱。前端必须使用维护活跃、基于 DOM 解析和允许列表的清洗器处理 Artifact HTML，推荐 `DOMPurify`。

允许的内容以可信 Renderer 当前输出为基线，包括文章结构标签、文本格式标签、图片、安全链接和经过约束的内联样式。至少禁止：

- `script`、`iframe`、`object`、`embed`、`form` 和可执行媒体节点。
- 所有 `on*` 事件属性。
- `javascript:` 和其他可执行 URL 协议。
- 未在资源策略中允许的远程资源和危险 `data:` URL。
- 能突破预览边界或覆盖工作台的危险样式。

清洗策略必须有独立测试。不得先清洗再通过字符串拼接加入不可信 HTML，以免使清洗结果失效。

预览清洗是前端纵深防御，不替代服务端 ArtifactBuilder 和 Renderer 的白名单校验。

## 资源地址处理

资源地址转换必须基于清洗后的 DOM 节点遍历，不再使用正则表达式修改整段 HTML：

1. 将 Artifact HTML 清洗为 inert DOM 或 `DocumentFragment`。
2. 遍历 `img[src]` 等受支持资源节点。
3. 仅解析 `/resources/...` 和 `/user-skills/assets/...` 等可信本地资源路径。
4. 通过现有鉴权资源 URL 解析器生成预览地址。
5. 拒绝未知协议和未授权资源来源。
6. 将完成转换的 fragment 挂载到 ShadowRoot。

图片加载失败时显示稳定的错误占位，不能改变手机视口宽度或导致工作台横向溢出。长图保持纵横比，GIF 保留浏览器原生播放行为。

## 预览、源码与复制

| 功能 | 数据来源 | 处理方式 |
| --- | --- | --- |
| 手机预览 | 原始 Artifact HTML | 清洗、解析可信资源、挂载 Shadow DOM |
| 源码 | 原始 Artifact HTML | 只读展示，不使用预览包装后的 DOM |
| 复制 HTML | 原始 Artifact HTML | 保持现有复制结果，不复制清洗器输出 |
| 兼容性提示 | Artifact Renderer warnings | 保持现有展示 |

如果清洗后内容为空或 ShadowRoot 创建失败，右侧显示明确预览错误状态，源码和复制功能仍可使用。不得静默回退为普通 DOM 注入。

## 实施阶段

1. 增加 `PhonePreview`、Shadow DOM 挂载和预览错误边界。
2. 引入并配置 HTML 清洗器，增加标签、属性、URL 和样式安全测试。
3. 将资源地址处理从字符串正则迁移为 DOM 节点遍历。
4. 固定手机逻辑内容视口，移除基于 `dvh` 和百分比压缩文章的规则。
5. 增加工作台横向滚动容器，统一三栏最小宽度，修订冲突断点。
6. 完成多分辨率行为验证和截图回归后，删除旧 iframe 预览路径。
7. 将完整手机设备固定缩放为 `80%`，右侧栏收紧至 `400px`，工作台基准最小宽度降至约 `1438px`。

迁移期间预览实现只能保留一个生产入口；不得长期同时维护 iframe 和 Shadow DOM 两套行为。

## 验收标准

- 在 `1920×1080`、`1536×864`、`1440×900`、`1366×768`、`1280×720` 和 `1024×768` 下，同一 Artifact 的标题换行、段落行数、图片位置和内容宽度一致。
- `1920 × 1080` 下手机视觉外框约为 `328 × 691.2px`，底部兼容性提示完整可见，中间创作区获得右栏释放的宽度。
- `1440px` 下展开状态的三栏工作台基本完整显示；`1280px` 及其他不足宽度下工作台出现横向滚动。
- 中间区不小于 `720px`，右侧保持 `400px`，手机逻辑内容保持 `390px`。
- `DeviceScaler` 固定使用 `80%` 视觉缩放；Shadow DOM 和文章内容不得缩窄或使用 `zoom`，文章只在手机内部纵向滚动。
- 缩放前后标题换行、段落行数、图片位置和内容顺序完全一致。
- 工作台 CSS 不改变文章样式，Artifact 内联样式不改变工作台 UI。
- 恶意标签、事件属性和危险 URL 无法执行或加载。
- 预览资源只能来自允许的本地资源路径或既定可信来源。
- 预览清洗和资源解析不改变源码展示及复制的原始 Artifact HTML。
- 切换预览与源码后内容完整，滚动和错误状态可预测。
