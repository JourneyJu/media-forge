# ADR 008：数据库模型配置与能力路由

## 状态

Accepted

## 日期

2026-07-30

## 背景

MediaForge 当前从 `MODEL_GATEWAY_*` 环境变量读取单一模型配置。该方案不能让管理员在部署后安全地维护模型，也不能表达纯文本和多模态能力之间的差异。

未来可能存在多个供应商连接、一个连接下多个模型，以及同一多模态模型同时承担文本和图文输入的情况。若把连接、密钥、模型和默认状态全部放在一张表中，会重复保存供应商密钥，并把模型生命周期与生产路由切换耦合。

模型配置变化会直接影响生成质量、可用性和成本，必须具备加密、验证、审计和可回滚能力。

## 决策

模型业务配置迁移到 PostgreSQL，并拆分为三层：

- `model_connections`：供应商协议、base URL 和加密凭据。
- `model_configs`：具体模型、模态、能力和运行参数。
- `model_routes`：系统能力到默认模型的唯一映射。

第一阶段只支持：

- `openai_compatible` adapter；
- `text` 和 `multimodal` 两种模态；
- `text_generation` 和 `multimodal_generation` 两条默认路由。

多模态表示文本和图片输入、文本或结构化输出，不包含图片生成。

请求是否包含图片决定路由。文本路由可以指向纯文本或多模态模型；多模态路由只能指向支持图片输入的多模态模型。

第一阶段不自动跨模型 fallback 或重试。配置不可用时返回稳定错误。

## 密钥决策

API Key 使用 AES-256-GCM 加密：

- 每条密钥使用独立随机 nonce；
- 数据库保存 ciphertext、nonce、auth tag 和 key version；
- 根密钥由部署环境或 Secret Manager 管理，不进入数据库；
- API 只允许写入和替换密钥，不允许读取；
- 响应只返回是否已配置；
- 支持按 `encryption_key_version` 轮换根密钥。

模型业务配置退出环境变量，不包括加密根密钥、数据库凭证和服务凭证等部署秘密。

## 路由一致性

- `model_routes.route_key` 全局唯一。
- 路由更新使用事务和乐观锁。
- 目标连接与模型必须为 `active` 且最近验证成功。
- 被路由引用的模型不能禁用。
- 存在启用模型或路由引用的连接不能禁用。
- 请求开始时生成不可变配置快照；路由切换不改变执行中的请求。
- API Key 不进入调用快照、日志、事件或用量记录。

## 备选方案

### 继续使用环境变量

优点：

- 实现简单。
- 不需要密钥加密表和管理页面。

缺点：

- 每次切换需要修改部署配置和重启。
- 无法提供管理员操作、能力验证和审计。
- 不能表达多模型和能力路由。

结论：拒绝。环境变量仅在旧版本回滚窗口暂时保留。

### 单一 `model_configs` 表

优点：

- 表和 API 更少。
- 第一版实现较快。

缺点：

- 同一供应商的多个模型会重复保存 base URL 和 API Key。
- 密钥轮换需要更新多条记录。
- 模型状态与连接状态耦合。

结论：拒绝，采用连接、模型和路由三层结构。

### 由前端本地存储模型

优点：

- 无需服务端管理 API。

缺点：

- API Key 会暴露给浏览器。
- 多用户环境无法统一管理和切换。
- 无法形成可靠审计和用量归属。

结论：拒绝。

### 自动 fallback 到其他模型

优点：

- 单模型故障时可提高可用性。

缺点：

- 可能重复计费。
- 不同模型输出行为和结构化能力不一致。
- 会使失败定位、审计和结果复现复杂化。

结论：第一阶段拒绝。后续如有明确 SLA 需求，单独设计带幂等、预算和审计的 fallback policy。

## 迁移

1. 新增三层表和管理 API。
2. 管理员手工添加连接与模型，不自动导入旧环境变量。
3. 完成连接和能力验证。
4. 配置两条默认路由。
5. 将 Model Gateway 配置解析切换到数据库。
6. 完成真实生成冒烟和观察。
7. 删除旧业务模型环境变量和兼容读取。

目标态没有环境变量 fallback。没有有效路由时返回 `GENERATION_MODEL_UNAVAILABLE`。

旧环境变量可在短期内留给上一版本代码回滚，但新版本不得读取。

## 后果

正向影响：

- 管理员可以在不改部署配置的情况下切换模型。
- 供应商凭据只保存一次，可以被多个模型复用。
- 纯文本和多模态调用具备确定性路由。
- 模型配置、验证、切换和禁用具备审计记录。
- 用量日志可以稳定关联 `model_config_id`。

负向影响：

- 新增三个领域对象、数据库表和管理 API。
- 需要可靠托管加密根密钥并演练轮换。
- 模型调用从同步环境变量读取变为数据库解析，需要处理不可用和并发切换。
- 第一阶段不自动 fallback，默认模型故障会显式影响生成可用性。

## 安全与运维要求

- 根密钥丢失会导致已存 API Key 无法解密，必须纳入 Secret Manager 备份。
- 根密钥泄露需要执行版本轮换和全部 API Key 重加密。
- 连接测试和能力验证只保存状态、耗时和安全错误码。
- 不记录完整供应商错误、Authorization header、密钥或敏感请求内容。
- 配置禁用优先于物理删除，以保留审计和历史用量。
