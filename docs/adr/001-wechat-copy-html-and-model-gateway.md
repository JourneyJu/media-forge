# ADR-001：微信公众号第一版采用富文本剪贴板和后端模型网关

## 状态

Proposed

## 日期

2026-07-26

## 背景

MediaForge 需要让普通用户生成公众号内容，并复制到微信公众号后台发布。需求包含 AI 生成、素材、文章版本、微信兼容 HTML 和模型配置。微信公众号后台对复制 HTML 有清洗和兼容性限制；直接发布需要额外的微信授权、素材同步和审核处理。

同时，模型供应商凭据属于敏感配置，不能暴露到前端，也不能让普通用户在生成工作台输入 API Key。

## 决策

第一版不直接调用微信公众号发布 API，只提供微信兼容富文本的剪贴板复制能力。该能力不是导出 `.html` 文件：service renderer 生成正文 HTML fragment，web 在用户点击后同时向剪贴板写入 `text/html` 和 `text/plain`。AI 调用统一由 `apps/service` 通过 Model Gateway adapter 执行。

HTML fragment 使用保守标签和内联样式，不包含完整 HTML 文档包装。图片只引用素材链路已有的 HTTPS 可访问 URL；第一阶段不新增图片代理、转存、素材包或微信素材库集成。浏览器不支持富文本剪贴板、权限被拒绝或 renderer 失败时，前端必须显式降级或报错，不能把纯文本结果报告为完整富文本复制成功。

模型配置分两层：

1. 第一版使用 `apps/service/.env` 提供系统默认模型。
2. 正式产品形态由管理与配额模块维护 `model_configs`，API Key 加密保存，前端不返回密钥明文。

文章正式版本必须保存结构化 `content_json` 和 HTML 快照 key。HTML 只作为可复现快照和复制导出结果，不作为唯一事实源。

## 备选方案

### 直接对接微信公众号发布 API

- 优点：用户可以一键发布。
- 缺点：授权、素材库、审核、失败回滚和多公众号权限复杂度高。
- 结论：第一版拒绝，后续作为独立 L 级变更评估。

### 前端直接配置模型 API Key

- 优点：开发简单，原型验证快。
- 缺点：泄露风险高，无法统一配额、日志和供应商路由。
- 结论：拒绝。

### 只保存 HTML，不保存结构化内容

- 优点：实现简单。
- 缺点：无法稳定编辑、修订、恢复、迁移 renderer，也无法做长期学习。
- 结论：拒绝。

## 后果

- 第一版用户需要复制到微信公众号后台手动发布。
- 标题、作者、摘要、封面和平台设置不属于正文剪贴板，仍由用户在公众号后台单独填写。
- service 必须承担模型调用、prompt 快照、用量日志和错误分类。
- renderer 需要维护微信兼容白名单和版本号。
- web 需要维护富文本剪贴板能力检测、纯文本降级和复制结果提示。
- 图片能否被微信公众号获取和转存依赖其公网可访问性及平台行为，最终兼容性必须通过真实公众号编辑器验证。
- 未来如果接入微信发布能力，需要新增授权、素材同步、发布状态和失败补偿，不应复用复制事件当作发布事实。
